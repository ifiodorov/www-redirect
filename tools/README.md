# og-шимы для превью в Telegram

## Зачем этот репозиторий делает больше, чем www-редирект

Краулер превью Telegram **не достаёт до боевого сайта на Timeweb** (апекс
`prosto-finance.ru`). Доказано пробами 21.07.2026: та же страница с картинкой,
лежащей только на апексе, до карточки не доезжает; с www - доезжает мгновенно.
Полный разбор - в основном репо проекта:
`plans/2026-07-15-telegram-og-preview-ne-podtyagivaetsya.md`.

`www.prosto-finance.ru` живёт на GitHub Pages, куда краулер ходит без проблем.
Поэтому здесь для каждой страницы сайта лежит **шим** - лёгкая HTML-страница с
og-тегами и картинкой, которая:
- отдаёт краулеру Telegram корректную карточку;
- живого человека мгновенно редиректит на апекс (JS `location.replace`).

**Ссылки в постах Telegram надо слать с `www.`** Для читателя разницы нет.

## Два правила, без которых карточка ломается

1. Никаких `canonical` и `meta refresh` на апекс - краулер уходит по ним на
   недоступный ему хост, и карточка пропадает.
2. `og:image` обязан лежать на www. Ссылка на картинку с апекса не сработает
   по той же причине - краулер туда не дойдёт.

## Третье правило: www держится вне поиска тегом, а не запретом

Каждый шим обязан нести `<meta name="robots" content="noindex">`. Его ставит
генератор, наличие проверяет `verify_shims.py`.

**В `robots.txt` запретов больше нет** (до 17.09.2026 там стоял `Disallow: /`
на каждого поисковика поимённо). Причина замены: запрет в robots.txt не прячет
страницу, а лишь не даёт её скачать. Google, узнав адрес со стороны, кладёт его
в индекс пустой строкой - без описания, и вычистить нечем, потому что `noindex`
он тоже не скачает. Так корень www и попал в индекс (письмо Search Console
от 15.09.2026, «Проиндексировано, несмотря на блокировку в файле robots.txt»).

Теперь робот заходит свободно, читает `noindex` и выбрасывает адрес из индекса.
На превью это не влияет: краулеру Telegram мета-тег `robots` безразличен -
в отличие от `canonical` и `meta refresh`, он никуда не уводит.

## Как обновить после новой статьи/страницы

Шимы НЕ обновляются сами. После публикации новой страницы на сайте:

```
python3 tools/build_shims.py     # снимет og с sitemap апекса, соберёт шимы, зеркалит картинки
python3 tools/verify_shims.py    # проверит, что все страницы и картинки отдаются краулеру
git add <новые файлы>            # поимённо
git commit && git push
```

`build_shims.py` идемпотентен: существующие картинки не перекачивает, шимы
перезаписывает свежими og с боевого сайта.
